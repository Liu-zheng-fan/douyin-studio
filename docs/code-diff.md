# 代码级对账：douyin-studio vs 五个参考项目

五个审计各自逐文件读过源码，结论重叠度很高。下面按「差距的性质」归类，不按项目罗列。

## 一句话结论

| 项目 | 它的强项 | 我的强项 |
|---|---|---|
| brewreel | **契约与校验的工程密度**（一镜一 spec、约 240 个校验点、生成式文档、版式自查） | 闭环与运营（审批箱/台账/复盘/成片质检） |
| fy-code-animation | **相机 + 场景可重叠**两个抽象 | 转场库、竖屏适配 |
| EAC | **色彩链路**（140 参数、11 步链、.cube 烘焙、NLE 导出） | 交付后质检 |
| vibe | **视觉成熟度**（bloom/颗粒/暗角、seek 契约、审片工具） | 音频总线、确定性帧模型 |
| directorx + dsh | **提示词准入闭环**（craftId、分级、反推、逐字裁决） | 合规层、CLI 契约、测试密度 |

## A. 结构性差距（四个，按严重度）

### A1 契约缺失：我有字段名清单，它有可执行契约

| | brewreel | 我（改前） |
|---|---|---|
| 每个镜头的参数 | `shots/*.spec.json`：113 处 `maxLen`、28 处 `format`、enum | `SHOT_FIELDS` 74 个字段名，**0 约束** |
| 超长怎么处理 | 校验拦下，报「第 N 镜 字段：问题 → 怎么改」 | `[:8]` **静默截断**，数据被吃掉 |
| 文档来源 | 从 spec 生成 `shots.md`（1,428 行） | schema/ SKILL/ 模板**三处手抄**，必然漂移 |
| 校验点 | 约 240 处 err/warn | 15 处 |

**已修**：`studio/specs.json` 成为唯一来源；`douyin/schema.py` 改成通用 walker，每条错误带 `fix`；删掉 4 处静默截断。校验器上线当天就抓到示例里的真错（`reveal` 缺 `text`）。

### A2 相机与场景重叠：我的画面只能顺序播放

fy 的 `CameraRig` 把世界层和字幕层分开，`cameraPath` 用一条曲线驱动运镜；`layoutScenes` 允许两镜在时间轴上重叠。我是 `for` 循环 + 复用上一镜末帧，**做不出任何需要双画面并存的转场**（iris、格栅、遮挡切）。

### A3 色彩链路：4 个参数 vs 140 个

EAC 的 `grading.mjs` 1025 行：HSL 分通道、曲线、蒙版、`.cube` 烘焙、11 步处理链。我的 `grade()` 只有 contrast/saturation/warmth/lift 四个参数、3 步、8-bit 截断。**产物带不出去**（没有 .cube，别人拿去用不了）。

### A4 视觉成熟度：没有后期，没有 seek

vibe 的三件套（bloom 两档、6 张颗粒轮换、暗角）+ `seek(t)` 契约 + 审片工具（stills/sheet/motion/det）。我：无后期（已补 `postfx.py`）、只能从头渲（改一个镜头要等 2 分钟）。

## B. 我更强的地方（别照抄丢掉的）

| 项 | 我的实现 | 参考没有 |
|---|---|---|
| 人工审批环 | `outbox.py` 六类拒绝标签 + `decision.json` 状态机 | brewreel 只有 `human` 清单，不等人按键 |
| 运营闭环 | `ops/` 583 行：闸门/台账/复盘/拉片/建议 | brewreel 到出片为止 |
| 成片质检 | `qc.py` 三级 + 数值阈值（黑帧/LUFS/开场帧差） | brewreel 只校 BGM 母带 |
| 合规层 | `compliance.py` 76 词 + AI 标识硬阻断 | 两个参考都没有广告法层 |
| 读音校正 | `pronounce.py` 53 条同音替换 + 数字读法 | directorx 有更全的 88 条，但没有我的数字处理 |
| 确定性 | 纯函数帧、无时钟无随机 | fy 依赖 Remotion 运行时 |

## E. 三个被审计揪出来的真 bug（已修）

1. `pipeline.py:153` **force 语义写反**：`--force` 本该放行，实际是强制拦截
2. `qc.py:135` **字幕检查不可达**：`subtitle_chars` 从来没人传，改成读 `meta.json`
3. `pronounce.py` 的 `check()` **是死代码**：只有"改"没有"验"，已接进 build

## F. 一条方法论

三个审计员独立指到同一处：**我擅长"闭环"，不擅长"契约"**。

闭环保证事情能做完，契约保证做完的是对的。我把 90% 的力气花在了"跑通"，剩下 10% 才碰"对"——所以 8 版之后，测试全绿、评分 280、质检 pass，画面还是空的。

**评分体系里没有的那一项，就等于不存在。**

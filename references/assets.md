# 素材与渲染：七种方案，什么时候用哪个

没有"最好的方案"，只有"这一镜该用哪个"。混用是正常的，只用一种才是问题。

---

## 一、七种后端

| # | 方案 | 擅长 | 不擅长 | 成本 |
|---|---|---|---|---|
| 1 | **Pillow 逐帧**（当前默认） | 文字、卡片、几何、逐字动效 | 粒子、形变、3D | 1080p 约 5 帧/秒 |
| 2 | **Canvas + Playwright** | 粒子、形变、CSS 动画、3D 变换 | 需要 Chrome，逐帧慢 | 约 2 帧/秒 |
| 3 | **Remotion** | React 组件级动画、复杂时间线 | 要 npm，配置重 | 视项目 |
| 4 | **ffmpeg filter graph** | 转场、调色、拼接、字幕烧录 | 逐帧文字动画 | **整段一次处理，最快** |
| 5 | **HTML/CSS 截图** | 排版、图表、Lottie | 同上 | 约 3 帧/秒 |
| 6 | **真实素材**（录屏/实拍） | 可信度最高 | 要人拍 | 一次拍摄 |
| 7 | **生成式视频（i2v）** | 把静图变成运动镜头 | 按秒计费，形象会漂 | 几元/条 |

## 二、决策树

```
这一镜要说什么？
├─ 一句话 / 一个数字 / 一个对比
│   └─ Pillow（文字卡）——确定性最强，最快
├─ 产品长什么样
│   ├─ 有实拍 → 真实素材（裁剪 + 轻微推近）
│   └─ 没有 → 即梦生图 + Pillow 运镜（标注 AI 生成）
├─ 一个过程 / 一个因果
│   └─ Pillow 的 line 镜头（连线动画）
├─ 情绪 / 氛围 / 转场
│   ├─ 轻量 → fields 程序化背景（噪声/粒子，26–43ms/帧）
│   └─ 要粒子形变 → Canvas（需要装 Chrome 自动化）
├─ 角色出镜（有透明 PNG）
│   └─ `char` 镜头：`characters/<角色>/<动作>.png`，文件名即动作名
└─ 真实世界
    └─ 录屏 或 手机拍——这是唯一能到"帧差 30+"的路
```

## 三、混用的正确姿势

一条 30 秒的片子完全可以这样：

| 镜 | 后端 | 理由 |
|---|---|---|
| 1 hook | Pillow + 逐字动效 | 0.5 秒内必须有事发生，Pillow 最快 |
| 2 数据 | Pillow number | 数字滚动要精确控制 |
| 3 产品 | 即梦生图 + Pillow 运镜 | 没有实拍 |
| 4 真实场景 | **手机拍的 3 秒** | 可信度 |
| 5 转场 | ffmpeg | 整段处理，比逐帧便宜 |
| 6 cta | Pillow | 同上 |

**判断标准**：这一镜的信息是不是"文字能承载"的？能 → Pillow；不能 → 换后端。

## 四、当前的实现状态（诚实版）

| 方案 | 状态 |
|---|---|
| Pillow 逐帧 | ✅ 已实现，9 种镜头 |
| 程序化背景 | ✅ 已实现（噪声/点阵/粒子/流场） |
| 即梦生图 | ✅ 已实现，带缓存 |
| 真实素材 | ✅ 已实现（broll 抽帧） |
| ffmpeg 转场 | ⚠️ 转场在帧层做了，还没下放到 ffmpeg |
| Canvas 引擎 | ❌ 未实现（需 Chrome + Playwright） |
| Remotion | ❌ 未实现 |
| 生成式视频 i2v | ❌ 未实现（要 Seedance 权限） |

## 五、为什么现在是 Pillow 优先

**因为链路最短**：改一行 JSON → 2 分钟出片 → 手机上能看。
Canvas 要起浏览器、等页面加载、逐帧截图，一条 30 秒的片子要 15 分钟——试错成本高一个量级。

**什么时候值得换**：当你发现"我在用文字解释一件本该由画面演的事"时。
那时候换 Canvas，只改 `render_frames()`，其余全不动。

## 六、一个反面教训

第一版我用 `reveal` 镜头画了一个矢量的不锈钢盆——椭圆加渐变，代码画的。
看起来像 2005 年的 PPT 剪贴画。

后来改成即梦生图（一次 0.2 元），产品质感直接不一样。
**能用生图解决的画面，别用代码画。** 代码画的是"关系"和"文字"，不是"东西"。

# 运营手册：把「每天一条」跑成环路

这是 `douyin-studio` 的判断层。工具在 `studio/`，判断在这里。

## 0. 三条不可妥协

1. **环路优先于产量。** 每天一条但不知道哪条有效，等于用同一份错误重复 30 次。宁可隔天一条，也要留下可比的变量。
2. **一次只改一个变量。** 同时改开头、封面、时长，数据涨了也不知道是谁的功劳。
3. **人只做两件事：给方向、点按钮。** 其余必须机器完成，否则「自动运营」是假的。

## 1. 每日时间轴

| 时间 | 动作 | 谁做 | 命令 / 产物 |
|---|---|---|---|
| 02:00 | 取昨日数据 | 机器 | 台账追加一条（`ops.ledger add`） |
| 02:05 | 复盘 + 定今日变量 | 机器 | 读 `ops/review.py`，决定今天只动哪一个变量 |
| 02:10 | 选题 | 机器（LLM）或人 | 写进 `选题` 字段，附「谁在什么场景为什么看」 |
| 02:15 | 写脚本 | 机器（LLM）或人 | `script.json` |
| 02:20 | 合规预检 | 机器 | `pipeline` 自动跑，`block` 就地重写 |
| 02:25 | 生图 | 机器 | `studio.imggen`，4 张候选选 1 |
| 02:40 | 渲染 | 机器 | `studio.pipeline` |
| 02:45 | 质检 | 机器 | `studio.qc`，`block` 直接回炉且不进队列 |
| 07:00 | 投递审批 | 机器 | `studio.outbox pack` |
| 08:00 | **审批** | **人** | 点通过 / 拒绝（拒绝必选理由） |
| 08:05 | 发布 | 机器 | 通过则发；失败重试 1 次后告警 |
| 全天 | 评论守护 | 机器 | 每 30 分钟拉新评论，按边界回复 |
| 22:00 | 数据入库 | 机器 | 次日中午后补结算值 |

**注意**：抖音的完播率/2 秒跳出是**次日中午**才结算的，08:00 看到的是实时播放数，只能当趋势，不能当结论。

### 队列纪律（硬规则）

**只要有一条没审批，就不生产新的。** `ops/daily.py` 会自动拦截并返回 `pending` 列表。
理由：待审队列一旦堆到两条以上，「早上顺手看一眼」就变成负担，人会直接不看——那时整套自动化就废了。

解冻方式只有两个：审批掉它，或者明确说「放弃这条」。

## 2. 选题

### 判准（三条全过才能做）

1. **一句话说得出「谁、在什么场景、为什么会看完」**。说不出来就换。
2. **能用一个可观察的变化承载**（数字变了 / 状态变了 / 关系变了）。只有观点的选题，画面会退化成字卡。
3. **和账号现有资产有关**：角色、产品、真实数据、真实困境。不相关的一次性热点不做——它带来的人不会留下。

### 配额（硬性，防止全变硬广）

| 类型 | 占比 | 例子 |
|---|---|---|
| 产品 | 40% | 盆的工艺、价格、使用场景 |
| 幕后/数据 | 30% | 今天赚了多少、哪条爆了、AI 出错合集 |
| 观点 | 30% | 为什么个体户要做内容、AI 带货的真相 |

连续两条同类型 → 第三条强制换。

### 常用选题来源

- **自身的真实数据**（最难得，别人抄不了）：粉丝数、播放、收入、被拒次数
- **评论区问题**：一条评论就是一条选题，回得好的那条扩成视频
- **同行的爆款做反向**：他们说 A，我验证 A 不成立
- **产品细节**：一个盆的厚度、重量、哪里会锈

### 禁做

- 蹭与账号无关的热点
- 纯口播念观点（没有画面变化）
- 「震惊体」标题配平淡内容
- 同一话题 7 天内重复

## 3. 脚本

骨架见 `templates/script-skeletons.md`。硬规则：

| 规则 | 数值 | 原因 |
|---|---|---|
| 总时长 | 25–40 秒 | 超过 45 秒完播率断崖 |
| 首镜 | 0.5 秒内必须有事发生 | 3 秒退出率是首要杀手 |
| 口播每句 | ≤ 18 字 | 长了听不清，字幕也折行 |
| 镜头数 | 5–7 | 少了拖，多了碎 |
| 屏幕字数 | 比口播更短 | 观众在读字就不听你说话 |
| 结尾 | 一个具体动作，不要「点赞关注」 | 泛号召无效 |

## 4. 人设

模板见 `references/persona.md`。核心三件：

- **角色资产固定**：鲸鱼娘的形象一旦定稿，就用固定提示词 + 固定 seed 复用，不每天重新设计。角色一致性 = 辨识度。
- **语气固定**：短句、少形容词、自嘲但不卖惨、不喊「家人们」。
- **视觉固定**：同一套配色与字体，允许换构图，不允许换风格体系。

## 5. 质检

`python -m studio.qc <mp4>`，判定三级：

| 级别 | 含义 | 处理 |
|---|---|---|
| `block` | 分辨率错、无音轨、时长越界、黑帧 >25%、开场死帧 | **回炉，不进审批队列** |
| `warn` | 响度偏离、峰值过高、字幕过长、黑帧 10–25% | 进队列，审批页标红，人自己判断 |
| `pass` | 无异常 | 正常投递 |

**为什么质检必须在投递前**：你早上只有 10 秒耐心，让一条「音轨是静音」的视频占掉这 10 秒，第二天你就不看了。

## 6. 审批协议

`python -m studio.outbox pack <dist>` → `python -m studio.outbox serve`（手机连同一 WiFi 打开）。

拒绝必须选一个理由标签，标签直接决定次日改什么：

| 标签 | 次日动作 |
|---|---|
| 选题不喜欢 | 换题材，优先补配额最低的那类 |
| 文案不像人 | 缩短句子、去书面词、加一个具体细节 |
| 画面丑 | 换构图/换风格处理，提示词加材质与光线 |
| 太慢 | 砍一镜，压到 25 秒内，开场提前到 0.3 秒 |
| 音频难听 | 换音色别名，BGM 降一档或换 mood |
| 不想发这个产品 | 加入产品黑名单，选题池移除 |

**连续两次同一标签 = 系统性缺陷**，要改的是模板，不是这一条片子。

## 7. 数据判读

| 指标 | 好 | 坏 | 说明 |
|---|---|---|---|
| 完播率 | > 40% | < 25% | 时长是否合适，第一看这个 |
| 2 秒跳出 | < 35% | > 60% | 开场是否抓人 |
| 播放量 | — | — | 是结果，不是原因，别拿它当诊断 |
| 播转粉 | > 1% | 0 | 人设是否成立 |

**样本纪律**：同组少于 6 条不下结论；组数控制 2–3 个；只看中位数，不看均值（一条爆款会把均值带偏）。

## 8. 故障决策树

| 现象 | 先查 | 动作 |
|---|---|---|
| 生图失败 | `--check` / `--models` | 重试 2 次 → 换模型 → 仍失败改纯文字镜头 |
| 出废图（多手指/文字乱码） | 提示词 | 加「简洁、干净背景、不要文字」，降复杂度重生成 |
| 渲染超时 | 帧数 | 降 720p，或砍镜头 |
| 质检 block | 具体 issue | 修根因，**不要 --force 绕过** |
| 审核被拒 | 拒因 | 改文案重投一次，二次失败转人工 |
| 限流/风控 | 平台通知 | **停更 48 小时**，只互动不发布 |
| 成本超支 | 台账 | 生图 ≤8 张/天，文本 ≤20 万 token/天，超了降级模板 |

## 9. 成本与频率红线

| 项 | 上限 | 说明 |
|---|---|---|
| 生图 | 8 张/天 | 同提示词命中缓存不计费 |
| 文本 | 20 万 token/天 | 够写 20 条脚本 |
| 发布 | 1 条/天 | 2 条以上审批会变成负担 |
| 连续发布 | ≤ 6 天 | 第 7 天停更，避免被判机器号 |

## 10. 账号安全

**触发停更的信号**（任一出现，立即停 48 小时）：

- 播放量突然归零但账号正常
- 收到「内容不适合推荐」通知
- 同一条视频反复审核不通过
- 登录态异常（提示异地/需要验证）

**不要做的事**：同设备多账号、固定整点发布、批量复制同一条文案、短时间大量关注/取关。

## 11. 明确不能自动的

- 实名认证、支付、平台资质申请
- 真人出镜、真实产品拍摄
- 平台审核结果
- 爆款（只能提高概率）

## 12. 接手自检

新会话接手时按顺序确认：

1. `python scripts/selfcheck.py` 全绿
2. `python -m studio.imggen --check` 为 `ready: true`
3. `ops/ledger.jsonl` 里最近 3 条的变量是什么，今天该动哪一个
4. `outbox/` 里有没有 pending 的决定没处理
5. 上一轮被拒绝的标签是什么——今天不能重复同一个毛病
